## 项目档案

### 架构与数据流

```
VPN Gate feed (https://www.vpngate.net/api/iphone/, 镜像 fdciabdul JSON)
   │ GitHub Actions cron */30
   ▼
vpngate.py (frontend, 1048行, R1-R9) ──GET /check?sstp=host:port──▶ CF Worker: checker
   │◀──── JSON {success, responseTime, colo, exit{…is_abuser,is_clean}} ────┘
   │ 二次复测(每国前8) ｜ 入口域名TLS自检 ｜ ban/pin 人工干预
   ▼ web/
GitHub Pages：data.json + index.html 面板 + nodes*.txt + subscription*
   ├─ A 端 gen_client_config.py → mihomo 四场景 select 组（CP_* 订阅=VLESS Worker 优选）
   └─ B 端 vpn_dial.py → OpenVPN 系统级拨号（不过 Worker，直连 VPN Gate 原生协议）
```

### 四场景判定标准（evaluate_stability，全部吃实测字段）

- ⭐客服: is_clean=True ∧ residential ∧ uptime≥12h ∧ sessions≤120 ∧ jitter≤150 ∧ lat≤600
- 🎮游戏: lat≤400 ∧ jitter≤100 ∧ sessions≤250 ∧ 非脏IP
- ⬇️下载: feed带宽≥2Mbps ∧ sessions≤250 ∧ lat≤2000
- 🤖AI: is_clean=True ∧ uptime≥6h ∧ jitter≤200 ∧ lat≤800
- 脏IP 永远进不了 客服/AI/游戏（pin 也不覆盖）

### 9 个修复（vpngate.py docstring R1-R9）

R1 parse_csv 不跳行不抬门槛缺列安全默认｜R2 无缓存兜底合并、无成功不发布｜R3 检测会话零重试｜
R4 复测区分业务失败/Worker抖动｜R5 cron30+超时25分钟｜R6 jitter未测=None、uptime=0=未知｜
R7 入口全失败返回完整列表+告警｜R8 无硬编码Worker地址｜R9 链接用SSTP_USER/PASS

### 测试方法论

改任何 Python 必须 `python test_*.py` 全绿才交付；Worker JS 改完 `node --check`
