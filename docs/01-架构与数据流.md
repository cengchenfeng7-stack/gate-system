## 前后端契约

### 请求

`WORKER_CHECK_URL`（形如 `https://<worker>.workers.dev/check?sstp=vpn:vpn@`）+ `host:port`

### 响应（前端 check_one 逐字段消费）

| 字段 | 含义 |
|---|---|
| `success` (bool) | 检测是否通过 |
| `responseTime` | 毫秒延迟 |
| `colo` | CF 边缘机房代号 |
| `error` / `message` | 失败原因 |
| `exit.ip/country/country_code/city/continent` | 出口地理 |
| `exit.asn.asn/org/name/type` | ASN 画像 |
| `exit.is_datacenter` | 是否机房 |
| `exit.is_abuser / is_tor / is_bogon / is_clean` | 风控四件套 |

## 数据流详解

### 1. 抓取（fetch_vpngate）

- 主源：`https://www.vpngate.net/api/iphone/`（CSV 格式）
- 回退：`https://raw.githubusercontent.com/fdciabdul/Vpngate-Scraper-API/main/json/data.json`
- 解析：`parse_csv`（R1: 不跳行、不抬门槛、缺列安全默认）

### 2. 筛选 SSTP 节点（to_sstp_nodes）

- 从 .ovpn 配置提取 `proto tcp` + `remote <host> <port>`
- 仅收 TCP 节点（SSTP 需要 TCP）
- 端口来源：ovpn remote port（实证可用：443/995/1298/1462/1961/5555 等）

### 3. 检测（check_all → checker）

- 并发 ≤16，零重试（429/5xx 直接判 Worker 异常）
- 二次复测：每国前 MAX_PER_COUNTRY+2 名，区分业务失败/Worker 抖动
- 复测成功：jitter = |lat2-lat1|，latency 取两次均值

### 4. 评级（evaluate_stability）

- 四场景判定（见 docs/00）
- 综合分 composite = lat + jitter*1.5 + 短命惩罚 + 拥挤惩罚 + 住宅惩罚 + 脏IP惩罚
- 分层：platinum（⭐客服稳连）/ gold（⚡高速稳定）/ standard（普通可用）

### 4.5 新分组（八分组面板）

| 分组 | 条件 | 说明 |
|---|---|---|
| 日常组 | 所有可用节点 | 默认视图 |
| 下载组 | speed_ready | lat≤5000 + 稳定（波动率<30%） |
| 游戏组 | game_ready | lat≤400 + 抖动≤100 |
| 客服组 | support_ready | 干净IP+住宅+长在线+低抖动 |
| AI组 | ai_ready | 干净IP+长在线+低抖动 |
| 机房组 | is_datacenter_node | 机房节点单独管理 |
| 养鱼组 | fish_ready | 稳定但暂不够格进四场景，观察中 |
| 观察组 | 不稳定但可用 | 波动大，待观察 |

### 4.6 历史缓存 + 自动黑名单 + 稳定性判定

- 缓存文件：`cache/nodes_history.json`（运行时生成，不提交）
- 每次 feed 返回的节点更新缓存（last_seen）
- 检测成功的节点记录延迟（最近 5 次）
- 连续 5 次失败 → 自动归入 ban.txt
- 缓存节点合并到检测队列（扩大检测池）
- 稳定性：波动率 = 标准差/均值，< 30% 为稳定；不稳定节点不能进需要稳定的场景

### 5. 产物（write_outputs）

- `web/data.json`：全量结构化数据（含四场景评级+养鱼池+机房+观察组）
- `web/index.html`：面板（读 data.json，八分组）
- `web/nodes.txt`：全量精选
- `web/nodes_support.txt` / `nodes_game.txt` / `nodes_speed.txt` / `nodes_ai.txt`：四场景
- `web/nodes_datacenter.txt` / `nodes_datacenter_premium.txt`：机房节点
- `web/nodes_fish.txt`：养鱼池
- `web/nodes_watch.txt`：观察组
- `web/subscription*.txt`：通用订阅
- `cache/nodes_history.json`：历史缓存（运行时生成，不提交）

## 客户端

### A 端（mihomo/Clash）

- `gen_client_config.py` 读 data.json → 生成 mihomo 配置
- 四场景 proxy-providers（CP_* 订阅地址 = VLESS Worker 优选）
- select 组，严禁 URL-Test（IP 漂移=客服/AI 掉线铁律）
- 域名分流规则（AI/客服/游戏/下载）

### B 端（OpenVPN）

- `vpn_dial.py` 自己抓 feed 取 .ovpn 配置
- 按场景挑候选（置顶优先、黑名单剔除）
- 生成 .ovpn + 凭证文件 → 启动 openvpn → 掉线自动换候选
- 不经过 Worker，直连 VPN Gate 原生协议

## 安全架构

- 源码零私有信息（R8: 不硬编码 Worker 地址）
- 公开产物只含公共信息（mask_worker_url 脱敏）
- 不打爆 Worker（零重试/并发≤16/复测只测前排）
- 失败不断线（无成功不发布、不清线）
