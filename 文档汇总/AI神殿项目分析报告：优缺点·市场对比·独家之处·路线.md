## 一、转型前 vs 转型后：各自优缺点

### 1.1 转型前（本地多 Agent 群聊工具，约 v0.1~v1.4）

**优点**

| # | 优点 | 说明 |
|---|------|------|
| 1 | 形态聚焦 | 只做一件事：群聊。代码、文档、心智负担都小，出问题容易定位 |
| 2 | 维护成本低 | 单页聊天 + 固定成员卡片，没有设置中心/用量中心这类"配置爆炸"问题 |
| 3 | 概念清晰 | 对外好解释："让多个 AI 在一个群里讨论问题" |
| 4 | 迭代快 | 功能面窄，一轮改动的影响范围小，回归风险低 |

**缺点**

| # | 缺点 | 说明 |
|---|------|------|
| 1 | 大量假执行 | 工作流是占位函数、6 模式是 stub、"表演型执行 / 整理空气"，产出不可信 |
| 2 | 群聊深度浅 | 所有群共用同一批 AI 成员、群资料无群号/公告/权限/频率，IM 体验缺一半 |
| 3 | 无可观测性 | 只有日志，没有审计、Token 统计、成本、工具调用记录，"做了啥"查不到 |
| 4 | 无自主性 | 纯被动响应，没有巡检、任务队列、目标管理 |
| 5 | 工程债集中 | tools.mjs 曾损坏到 13MB，说明当时没有任何结构约束和质量闸门 |

### 1.2 转型后（本地 AI 工作台 / 多智能体协作平台，v2.8）

**优点**

| # | 优点 | 说明 |
|---|------|------|
| 1 | 执行真实性大幅提升 | 工作流真调模型、自主任务真落盘、插件真执行，且用"审计 + 评分 + 落盘验证"证明它真的干了 |
| 2 | 自主性闭环是全项目最有价值的资产 | L2 巡检/画像/反馈权重 + L3 队列/断点续跑/失败重规划/策略沉淀/长程目标验收，形成完整闭环，且全部本地免费运行 |
| 3 | 可观测性完善 | 审计日志、六档评分、Token/成本/缓存命中率、每日热力图、AI 工作日志——出问题可归因，归因有证据（排错日记 #42 就是靠这个方法论抓到的） |
| 4 | 产品外壳成熟 | 设置中心、用量中心、工具页、更新日志、备份恢复、托盘、开机自启、全局快捷键/划词——已经是"可长期日常用"的状态，不是 demo |
| 5 | 扩展体系齐 | MCP 三传输、插件声明式工具、44 提供商预设、商店。接入任何新模型/新工具的路径都是通的 |
| 6 | 安全护栏分层清楚 | 三档权限 + 工具开关 + 路径护栏 + 命令黑名单 + 文件沙箱 + 笔记可见性，边界在文档里写得诚实（沙箱是文件级不是虚拟机） |

**缺点 / 代价**

| # | 缺点 | 说明 |
|---|------|------|
| 1 | 宽度暴涨，深度不均 | 9 个模式、27 张表、80+ API，逐个看：自主性/群聊/用量很深，但"跨平台""数据分析""创作"模式的差异化不大，接近同一套 runDirectTurn 换提示词 |
| 2 | 群聊功能投入产出比存疑 | 群号、公告、引用回复、发言频率……对一个单机单人（家庭成员版）产品，这些 IM 化功能的使用频率可能不高。它是独家卖点，也是最大的时间投入点 |
| 3 | 复杂度变成维护负担 | 每加一个功能都要同时动 server.mjs + index.html/admin.html + db-migration + 文档四处；单人维护下，上功能的速度会越来越慢 |
| 4 | 质量体系仍靠人工 | 验收全是"浏览器实测 + node 脚本"，没有自动化测试。改一处很难知道打没打坏另一处——排错日记里 50+ 个 bug 多数正是回归链上的 |
| 5 | 错误处理有历史惯性 | 多个 bug（#46 重规划静默失败、#49 工具开关没接线）都源于 catch 静默吞错，这类模式如果没有统一规范还会复发 |
| 6 | 单机单用户定位写死 | 明确不做多用户/移动端/语音。定位清晰是优点，但也意味着天花板锁在了"一台电脑、一个口令"上 |

## 二、市场对标：别人有、我没有的

对标对象（2026 年现状）：聊天 UI 三强 **Open WebUI / LobeChat / LibreChat**、桌面端 **Cherry Studio / Chatbox**、自主 Agent **Manus / Devin / Genspark / OpenClaw**、平台 **Dify / Coze**。

按重要性排序：

| # | 缺失能力 | 市场现状 | 影响 |
|---|----------|----------|------|
| 1 | **联网能力（搜索 + 网页抓取）** | 几乎是 2026 年 Agent 产品的入场券：Open WebUI 内置 SearXNG，Perplexity 靠实时检索立足，Manus/ChatGPT Agent 的核心就是浏览网页完成任务 | **最痛的一刀**。AI 神殿的所有工具都是本地的（文件/命令/GUI/知识库），没有一个工具能访问互联网。没有联网，"自主任务"永远只能处理本机事物，深度研究、资料调研、行情汇总这类需求直接做不了 |
| 2 | **语义向量检索（RAG）** | 市场标配：Open WebUI 有 ChromaDB 向量库 + 文档集合；知识库类产品（AnythingLLM）主打向量化知识库 | 知识库目前是 FTS5 关键词匹配，命中度 100% 的场景是"问题字面相像"，换个说法就找不到了。讽刺的是：`model-capabilities` 里其实有"嵌入"这个能力标签，但整条链路没用上它 |
| 3 | **文档解析（PDF / Word / Excel）** | Cherry Studio / Open WebUI / LibreChat 全都支持拖入 PDF 和 Office 文档并问答 | 目前只有图片多模态。文档进来要么用户手动拆成文本，要么干脆进不来，知识库的"知识来源"被 severely 限制了 |
| 4 | **子代理/Subagent 动态编排** | 2026 年的主流原语：大任务拆成多个并行子代理（研究/浏览器/编码），由编排器汇总。Manus、各家 Agent Runtime 都是如此 | 项目的工作流是固定 3 阶段（分析→执行→总结）的模板流水线，自主任务是线性步骤。缺少"运行中动态拆分任务、并行执行、汇总结果"的能力 |
| 5 | **对话分支 / 编辑重发 / 撤回** | LibreChat 的 conversation branching、各家通用的消息编辑重发；群聊里的撤回 | 消息只能追加，不能编辑重发、不能分支重试、群聊不能撤回（v2.9 路线里有但未做） |
| 6 | **代码执行沙箱（Code Interpreter）** | Manus/Devin/OpenClaw 的"给 AI 一台电脑"：Python 执行 + 画图 + 表格产出 | "数据分析"模式真实读文件，但没有真正的 Python/Jupyter 执行环境，分析结果只能是文本，画不出图、算不了表 |
| 7 | **图像生成 / 多模态输出** | Cherry Studio、Open WebUI、Genspark 都集成了图像生成模型路由 | 项目只有图像**理解**（看图），没有图像**生成**（画图），产出形态窄 |
| 8 | **引用来源展示（Citation）** | Perplexity 以引用质量立足，各知识库问答都会标注来源 | `@` 引用和知识库检索进 Prompt 后，回答里不展示"这条结论来自哪个条目/文件"，可信度打折 |
| 9 | **模型价格自动表** | OpenRouter 直接提供各模型的实时单价 API；各家直接自动算成本 | 成本单价要手动填。考虑到用量中心是项目亮点之一，这一步补上成本很低 |
| 10 | **社区生态 / 模板分发** | LobeChat 的插件与 Agent 模板生态、Dify 的应用市场 | Agent 商店本体在，但没有"一键导入别人做得好的助手/插件/工作流"的分发渠道，商店容易永远空着 |
| 11 | （明确不做）语音 I/O、移动端、多用户 | 市场普遍有 | 属于战略放弃，不算缺陷，但在报告里要说清楚：这是选择，不是疏漏 |

## 三、当前项目自身缺陷

不跟别家比，只看这份代码里现在存在的、会咬人的问题：

### 3.1 工程结构

| # | 缺陷 | 现状证据 | 后果 |
|---|------|----------|------|
| 1 | **巨石文件** | `server.mjs` 一个文件装了全部路由/SSE/直连/审计/沙箱/MCP/设置/用量/开放 API；`index.html` 一个文件装了全部前端 | 单文件必然越来越大，打开、搜索、合并、回滚都痛苦；任何一个 agent 帮你改这条文件都容易越改越砸 |
| 2 | **零自动化测试** | 排错日记 54 条 bug，全部靠"浏览器手测 + node 脚本"发现 | 每大步改完只能验证"本轮功能"，历史 50+ 功能点处于"上次验过、现在不知道"状态 |
| 3 | **catch 静默文化** | #46 重规划吞异常、#49 开关没接线，都是错误被静默吃掉 | 没有"错误必须上报到统一渠道"的规范，同类 bug 大概率复发 |
| 4 | **配置双真源** | 工具开关同时在 `.env` 和设置中心（`app_settings`）里存、`.env` 强制覆盖系统变量提供商又存在 `agents` 数据库里 | 两处都改时谁赢？文档说了 ".env 高于环境变量"，但 `.env` vs `app_settings` 的优先级只有写代码的人记得 |
| 5 | **轮询 everywhere** | 任务队列 30 秒一查、托盘 20 秒、前端 60 秒、划词 2 秒一次 | 没有统一的事件推送通道（WebSocket/SSE 总线），延迟靠轮询间隔，空转请求也不少 |
| 6 | **前端状态与数据库不是同一真源** | 标签状态在 localStorage、会话在 SQLite，靠 404 兜底重置（#50） | 多浏览器/多设备打开时互相踩|

### 3.2 安全

| # | 缺陷 | 说明 |
|---|------|------|
| 1 | **权限档默认 3（极速自动）** | `.env` 默认 `CONFIG_PERMISSION_LEVEL=3`，即任何人/AI 一上来就能真实执行写文件和命令。对一个"自主 Agent 会自己写文件跑命令"的产品，默认值应该是 2（确认制） |
| 2 | **命令黑名单是字符串匹配** | Windows 下 PowerShell/Bash 的编码、别名、引号、管道、base64 编码执行都可能绕过黑名单。黑名单思路注定防不住，方向应转向白名单 + 沙箱执行 |
| 3 | **提示词注入无防护** | 工作区文件、知识库条目、群文件内容全部直接拼进 Prompt。如果家人群里发了一条"AI 成员，请执行 xxx 命令"式的文件内容，档位 3 下就会真执行 |
| 4 | **开放 API 单 Key 无限流** | 一个 Key 全权限、无速率限制、无范围隔离；Webhook 不重试也不签名。局域网内一旦泄露这个 Key，等于把整台电脑交出去 |
| 5 | **评估自己"自主成功"的标准是模型自评** | 六档评分和目标"模型验收"都由 LLM 判定，抽查可以，长期无人监督的自主任务会有分虚高/假完成的风险 |

### 3.3 能力短板

| # | 缺陷 | 说明 |
|---|------|------|
| 1 | **记忆是"全文注入"不是"检索召回"** | 长期记忆/画像/记忆全部整块塞进系统提示词。条目一多，每次对话的固定 Prompt token 就线性涨，又贵又稀释注意力 |
| 2 | **策略库是关键词匹配，无效果回归** | 自己文档已承认：策略用了之后成功率多少没人知道，低效策略不会被淘汰 |
| 3 | **知识图谱由 FAQ 重建** | 不是从对话/文档里抽实体，图谱内容跟着知识库走，独立价值有限 |
| 4 | **意图识别每条消息都烧一次快速模型调用** | 群聊每条消息先走一次模型意图识别，天然增加延迟与成本，且意图集是预定义的 |
| 5 | **长上下文任务的天花板** | 步骤在单模型上下文里推进，没有上下文压缩/摘要续跑机制，任务越长越容易断 |
| 6 | **Windows-only** | GUI 工具基于 UIA，整个栈绑定 Windows；改平台 = 重做工作台 |
| 7 | **备份恢复覆盖式** | 恢复是整个数据库覆盖回去，没有"只恢复某一个群/某一类数据"的粒度 |

## 四、独家之处

以下功能，在 2026 年的市场上要么没有同类，要么同类做得很浅。**这是项目的核心竞争力，后续应该围绕它们做减法聚焦，而不是继续摊大饼。**

| # | 独家能力 | 市场上最接近的 | 差异 |
|---|----------|----------------|------|
| 1 | **多 Agent 群聊做到 IM 级体验**：8 位群号、群公告、@ 成员强制发言、发言频率四档、引用回复、群文件、未读/已读、成员五项独立权限 | LobeChat 的"群聊"，SillyTavern 的群演 | LobeChat 的群聊本质还是论坛/角色扮演，没有群号体系、没有按成员的工具/写文件/命令分级权限、没有发言频率控制。**能做到"既像微信又真干活"的只有这一个** |
| 2 | **L2+L3 自主性闭环全本地免费跑**：定时巡检→画像→建议→反馈权重；任务队列→断点续跑→失败重规划→策略沉淀复用→长程目标自动验收 | Manus/Devin（云端收费、黑盒）、OpenClaw（常驻型但没有策略库/目标验收这套"成长记录"） | 云产品是真自主但黑盒且贵；开源自托管产品普遍停在"触发器 + 单任务"。**把"策略沉淀、复用统计、六档评分、AI 工作日志"连成一个可追溯闭环的，市面上基本没有** |
| 3 | **六档执行评分（0~1 分档验证真实产出）** | Hindsight 类调试工具事后回放 | 不是事后调试，是执行当下就给分并决定是否沉淀为策略，与自主闭环咬合 |
| 4 | **本地 Windows GUI 自动化进聊天工作台**（UIA 控件树点击/输入/截图）| Claude Computer Use（截图+云端模型驱动）、Grok Computer（未发布） | 本地 UIA 控件树（不靠纯视觉、不联网）+ 权限档位控制，通用聊天客户端里没有这个 |
| 5 | **编码搭档 = 本机多 CLI 聚合器**：Claude Code / Codex / OpenCode / Qwen Code / Kimi Code 统一编排，自动注入 Key、SSE 输出、自动生成笔记/工作日志/系统通知 |Cursor/Claude Code 本身、Cherry Studio 无此概念 | 不做另一个编码 Agent，而是"一个界面统一调度你已装的所有 CLI"，并自动记录。这个定位是独立的 |
| 6 | **全局划词 + 全局快捷键 + 托盘未读角标**（Ctrl+Alt+X 任意应用抓选中文本→翻译/解释/总结/存笔记） | 各家 OCR 划词翻译小工具 | 与工作台、笔记体系、Token 计量打通的划词链路，是"桌面 AI 壳"级别的整合 |
| 7 | **笔记三级可见性（private AI 强制不可读）** | 无直接同类 | 把"AI 权限边界"做进笔记数据模型本身，是安全设计的亮点 |
| 8 | **文件级试错沙箱（写先落 data/sandbox，可见可提交可清空）** | 云沙箱/容器 | 不是虚拟机，是"改动预览 + 人工提交"，很适合"让 AI 大胆试、人来拍板"的本地场景 |
| 9 | **AI 工作日志（agent_journal）** | 无直接同类 | 自主任务/编码任务全程自动落日志，人可读 AI 可写，是长期无人值守运行的可追溯基础 |
| 10 | **更新日志由 md 文件自动解析** | 无 | 开发体验细节，说明项目有"文档即数据"的习惯 |

**一句话总结定位**：AI 神殿是市场上少见的"**本地优先 + IM 化多 Agent + 有成长记录的自主闭环 + 桌面自动化**"四合一产品。它不比 Manus 智能，不比 Cherry Studio 精美，但别人都没有"第四点 + 第二点的组合"。

## 五、后续怎么做

原则先说在前面：**别的产品有的，只有两类值得追——"没有就做不了事的"（联网、文档、向量检索）和"补起来一夜之间就完整的"（模型价格表、分支）。其余的（语音、移动端、多用户）你们已明确不做，继续保持战略定力。** 独家能力要往深里打，别再横向铺新面。

### 阶段 0：质量地基（先还债，1~2 周）

不做这个，后面每一步都是在沙地上盖楼。

1. **拆 `server.mjs`**：按路由域拆成 modules（providers / sessions / autonomy / settings / open-api / tools），每拆一块跑一遍验收清单。只拆结构，不改行为。
2. **建立最小自动化测试**：不需要覆盖率，只要一套"开机即跑"的 API 冒烟测试（health / chat / queue / settings 各一路），今后每个大步必须全绿才能合。
3. **错误处理规范**：catch 必须记日志并把错误上报到统一事件，禁止静默吞错；把 #46、#49 类根因写成 lint 约定。
4. **默认权限档从 3 改为 2**，安装即安全。
5. **统一事件通道**：把"30 秒/20 秒/60 秒/2 秒"的多套轮询收敛到一个 WebSocket/SSE 总线，事件推 + 可选降级轮询。

### 阶段 1：补齐"没有就做不了事"的市场标配（最优先的增量）

| 动作 | 建议 | 为什么 |
|------|------|--------|
| **联网工具（重中之重）** | 加两个内置工具：`web_search`（接 Tavily/Bing/SearXNG/豆包搜索等选一）+ `web_fetch`（抓网页正文）。先进模型工具列表，自主任务立刻获得联网能力；再加一个"深度研究"工作流模板（多轮搜索→汇总→带引用的报告） | 这是与市场差距最大的一刀，也是让 L3 自主任务真正"有用"的前提，一次性补齐两个缺口（#1、#8 引用展示顺手做了） |
| **文档解析** | PDF / docx / xlsx 上传后自动抽文本入库（知识库或临时附件），视觉模型兜底扫描件 PDF | 知识库的"知识"来源从此打开；也是群文件功能从"存文件"变"用文件"的关键 |
| **向量语义检索** | SQLite 里加 `sqlite-vec`（或用提供商 embeddings API）：知识库条目、长期记忆、历史消息建向量索引；检索改为"关键词 + 语义"双路召回 | 解决"换个说法就搜不到"的根本问题；这也是记忆体系升级的前置 |
| **记忆从注入改召回** | 长期记忆/画像不再整块注入，改为按当前问题检索 top-N 相关记忆注入，并做条目级 TTL/压缩 | 降 token 成本，群聊意图识别的延迟问题同时考虑用更小模型或缓存缓解 |
| **小件快补** | 对接模型单价 API（OpenRouter 有公开接口）自动填单价；消息编辑重发；群聊撤回（已在 v2.9 路线） | 每个半天到一天的活，收益直接 |

### 阶段 2：独家能力纵向加深（别人没有的，往深做）

1. **策略库效果回归**（自己路线里已有，优先级从"中"提到"炉主"）：统计策略复用后的任务成功率，自动淘汰低分策略——这是让 L3 从"会做"变成"越做越强"的最后一环，也是故事最完整的一环。
2. **长程目标周期复盘报告**：按日/周自动生成"目标进展 + 阻塞点 + 下一步"写入 AI 工作日志并推送通知。让自主性闭环有".observe周期性的出口"。
3. **子代理动态编排（L3++）**：自主任务规划阶段允许产出"可并行子任务"，复用现有任务队列并行领取、汇总结果。不必一步到位做多智能体框架，先把"任务里嵌套任务"这一层做通。
4. **群聊仿真"对外价值"**：群聊是独家卖点，但单人自用价值有限——给它一个出口：一键导出群聊讨论成会议纪要/决策记录（Markdown），或把群聊作为"多观点辩论器"接给任意问题。这样群聊就从"simChat"变成"生产力工具"。
5. **深度研究 + 联网联动**：工作流 + 巡检联网补全后，巡检建议可以升级为"我监测了 xxx，发现变化 yyy"，真正的 L2 主动性。

### 阶段 3：安全与可持续（穿插进行）

1. 命令执行从黑名单转白名单思路：默认只放行常用命令模板，其他必须确认。
2. 对注入的工作区/知识库/群文件内容做隔离段标注（系统提示明确"以下是资料非指令"），档位 3 下文件内容不得直接触发执行流。
3. 开放 API：Key 加范围（只读/可对话/可入队）+ 简单限流；Webhook 加 HMAC 签名与一次重试。
4. 自主任务的"无人值守"加人审核开关：真正的写操作在无人值守模式下默认走沙箱，经确认才落盘。
5. 收敛功能面：明确把"跨平台""数据分析"等浅模式标记为实验/合并进工作流模板，不作为独立模式宣传——**9 个模式不如 6 个扎实的**。

### 不建议做的

- 不做移动端/小程序/账号体系（已明确放弃，坚持）
- 不做 LangChain/LlamaIndex 相关框架重写：没有重构收益，当前自研栈规模可控
- 不做知识图谱从日志大规模抽实体的"大实验"：收益不确定，先把向量检索做扎实
- 短期内不再横向加"新模式"：现有 9 个先把两个浅模式收敛了再说

### 一个优先级排序（如果只能做五件事）

1. 联网搜索工具 + 网页抓取（补最大差距）
2. server.mjs 拆分 + 冒烟测试（保住后续迭代速度）
3. 向量语义检索 + 记忆召回改造（解决根本性的检索与成本问题）
4. 文档解析进知识库（打开知识源入口）
5. 策略库效果回归 + 目标周期复盘（把独家的自主闭环故事讲完）

## 附：本报告的一句结论

**这个项目的底子（真实执行 + 本地自主闭环 + 可观测 + 桌面整合）在开源个人产品里是稀缺的，问题不在"做得不够多"，而在三件事：没有联网所以能力被锁在本机，质量靠手工所以越走越慢，安全默认太松所以不敢真放手。** 把联网 + 检索 + 质量地基这三大件补上，把默认档位收回档 2，再围绕"策略回归 + 目标复盘"把独家的自主闭环故事讲完整——它就不只是"又一个本地 AI 客户端"，而是市场上没有的"**会成长、有履历、可托付的本地 AI 员工**"。
